# litmap cluster — Design Spec

**Date:** 2026-04-18
**Status:** Approved for implementation planning

---

## Goal

Add a `litmap cluster` command that groups a set of Zotero papers into a semantic hierarchy (up to two levels), labels each cluster with characteristic keywords, and produces both a dendrogram (HTML + PDF + PNG) and an outline (Markdown + JSON). Inputs: a Zotero collection, a manuscript bibliography, a whole library, or a union. The JSON output is complete enough to drive a future `litmap reorganise` command without re-computing.

## Non-goals

- Reorganising Zotero collections automatically. The JSON carries the full assignment; actually modifying Zotero is out of scope for this feature.
- Cluster labelling via LLM (API or local). Out of scope; labels are generated by TF-IDF keyword extraction.
- Influence of existing Zotero sub-collection structure on the clustering itself. Existing sub-collections appear only as annotations in the output for auditing.
- Three or more levels of hierarchy.

## User interface

```
litmap cluster [OPTIONS]

Options:
  -c, --collection TEXT           Zotero collection (or omit for whole library)
  -m, --manuscript PATH           Bibliography from a paper (PDF/DOCX/.bib/.tex)
      --union                     Use collection ∪ bibliography
      --top-clusters INT          Number of level-1 clusters
                                  [default: round(sqrt(N/2))]
      --subcluster-threshold INT  Min cluster size that triggers level-2 split
                                  [default: 20]
  -o, --output PATH               Output base path [default: litmap_cluster]
  -f, --format TEXT               html | pdf | png | md | json | all
                                  [default: all]
```

With `--format all`, the command writes `<output>.html`, `<output>.pdf`, `<output>.png`, `<output>.md`, `<output>.json`.

Paper-set assembly rules exactly match those of `litmap map`:

- `--collection X` alone → papers in that collection
- `--manuscript Y` alone → papers from Y's bibliography matched against Zotero
- `--collection X --manuscript Y --union` → union of the two
- `--collection X --manuscript Y` (no `--union`) → error with message *"pass `--union` to cluster both, or pick one"*. The "manuscript as a separate node" concept from `litmap map` does not apply to clustering.
- no flag → entire Zotero library

## Data flow

```
1. _auto_sync()                         [embed any new Zotero items first]
2. Resolve paper set
3. Load embeddings for that set         [matrix, N × 768]
4. Fetch per-paper existing sub-collection membership
5. compute_hierarchy(matrix)            [scipy linkage matrix]
6. cut_levels(linkage, top_k, subcluster_threshold)
     → assignments: [{key, cluster_id, subcluster_id|None}, ...]
7. label_clusters(items, assignments, level="cluster")
8. label_clusters(items, assignments, level="subcluster")
9. build_outline(items, assignments, labels, subcollections, input_meta)
10. Render requested formats
```

Every command call begins with `_auto_sync(db_path, zotero_db)` so the embedding cache is current before clustering — consistent with the existing `map`, `search`, and `sync` commands.

## Clustering algorithm

- **Distance:** cosine (1 − cosine similarity) on the stored 768-dim embeddings. Consistent with `litmap search` and `litmap map`.
- **Linkage method:** `average`. Average linkage is appropriate for cosine distance; Ward requires Euclidean and is therefore unsuitable.
- **Library:** `scipy.cluster.hierarchy.linkage`. The linkage matrix doubles as the dendrogram data source.
- **Level-1 count:** if `--top-clusters` is omitted, use `max(2, round(sqrt(N / 2)))` where N is the number of papers. This is a standard rule-of-thumb scaling (50 → 5, 500 → 16, 5000 → 50).
- **Level-2 splitting:** for each level-1 cluster with size ≥ `--subcluster-threshold` (default 20), re-cluster just that cluster's papers into `max(2, round(sqrt(size / 2)))` sub-clusters via a fresh `linkage` + `fcluster` call on the sub-matrix. Papers in smaller clusters have `subcluster_id = None`.
- **One-level mode:** users can force flat clustering by passing `--subcluster-threshold 99999`.

## Cluster labelling

- Corpus: one "document" per cluster, built by concatenating `title + " " + abstract` for every paper in the cluster.
- Vectoriser: `sklearn.feature_extraction.text.TfidfVectorizer` with `stop_words="english"`, `min_df=1`, `max_df=0.8`, `token_pattern=r"(?u)\b[A-Za-z][A-Za-z-]{2,}\b"` (reject tokens under 3 chars and purely numeric tokens).
- Label: top 3 terms per cluster by TF-IDF score, joined by ` · `.
- Runs independently at level 1 and level 2. A sub-cluster's label is computed against all *other* sub-clusters (not the level-1 clusters) so the terms are distinctive within that branch.
- Fallback: if a cluster has only one paper, its label is the paper's first 5 title words.

## Output contract

### JSON (`<output>.json`)

Canonical source of truth. All other outputs render from this.

```json
{
  "input": {
    "collection": "My Papers",
    "manuscript": null,
    "union": false,
    "n_papers": 247
  },
  "params": {
    "top_clusters": 11,
    "subcluster_threshold": 20
  },
  "clusters": [
    {
      "cluster_id": 1,
      "label": "species distribution · MaxEnt · GBIF",
      "size": 38,
      "subclusters": [
        {
          "subcluster_id": 1,
          "label": "remote sensing · Landsat · NDVI",
          "size": 12,
          "papers": [
            {
              "zotero_key": "ABCD1234",
              "title": "Machine learning in species distribution modelling",
              "authors": ["Valavi", "Elith"],
              "year": "2022",
              "doi": "10.1111/geb.13476",
              "existing_subcollections": ["Chapter 2", "ML methods"]
            }
          ]
        }
      ],
      "papers": []
    },
    {
      "cluster_id": 2,
      "label": "functional diversity · trait-based ecology",
      "size": 14,
      "subclusters": [],
      "papers": [
        {
          "zotero_key": "EFGH5678",
          "title": "Functional diversity: a review",
          "authors": ["Petchey"],
          "year": "2006",
          "doi": "10.1111/j.1461-0248.2006.00924.x",
          "existing_subcollections": []
        }
      ]
    }
  ]
}
```

Invariants:
- `size == len(papers) + sum(sc.size for sc in subclusters)`
- If `subclusters` is non-empty, `papers` is empty (papers live in sub-clusters when level-2 applies).
- If `subclusters` is empty, all papers live directly in `cluster.papers`.
- `existing_subcollections` lists the immediate collections the paper sits in (not inherited from parent collections). Empty list means the paper is only at the library root.
- `cluster_id` is 1-indexed and stable within a single run (order reflects left-to-right dendrogram order).

### Markdown (`<output>.md`)

Renders directly from the JSON. Cluster sizes in parentheses; existing Zotero sub-collections shown in brackets when present.

```markdown
# litmap cluster — My Papers (247 papers)

## 1. species distribution · MaxEnt · GBIF  (38 papers)

### 1.1 remote sensing · Landsat · NDVI  (12 papers)
- Valavi et al. 2022 — *Machine learning in species distribution modelling*
  [in: Chapter 2, ML methods]
- …

### 1.2 biotic interactions · co-occurrence  (8 papers)
- …

## 2. functional diversity · trait-based ecology  (14 papers)
- Petchey 2006 — *Functional diversity: a review*
```

### Dendrogram HTML (`<output>.html`)

Interactive Plotly dendrogram. Leaves labelled with short paper references (first-author + year). Hover on a leaf shows the full title and zotero_key. Coloured by level-1 cluster assignment. Full page, CDN-served Plotly.

### Dendrogram static (`<output>.pdf`, `<output>.png`)

Matplotlib rendering of `scipy.cluster.hierarchy.dendrogram`, 300 DPI, with level-1 cluster colour threshold set so the top clusters are visually separated. Leaves labelled with author-year. Same colour scheme as the HTML variant.

## Module structure

All new code lives in two new files plus a small addition to `litmap/zotero.py`. No existing modules are modified except `zotero.py` (one new function) and `cli.py` (one new command).

```
litmap/
├── cluster.py          [NEW] compute_hierarchy, cut_levels, label_clusters, build_outline
├── cluster_render.py   [NEW] render_dendrogram_html/static, render_outline_markdown/json
├── zotero.py           [MODIFY] + get_subcollection_map()
└── cli.py              [MODIFY] + cluster_cmd()
```

### `litmap/cluster.py` — public interface

```python
def compute_hierarchy(matrix: np.ndarray) -> np.ndarray:
    """Return a scipy linkage matrix (shape (N-1, 4)) from an N×D embedding
    matrix using cosine distance and average linkage."""

def cut_levels(
    linkage: np.ndarray,
    keys: list[str],
    matrix: np.ndarray,
    top_k: int,
    subcluster_threshold: int,
) -> list[dict]:
    """Return [{key, cluster_id, subcluster_id|None}, ...] in input order.
    Level-2 sub-clustering is only applied to level-1 clusters with
    size >= subcluster_threshold; it recomputes linkage on the subset."""

def label_clusters(
    items: list["Item"],
    assignments: list[dict],
    level: str,  # "cluster" or "subcluster"
    top_n_terms: int = 3,
) -> dict:
    """Return {cluster_id: label_string} or {(cluster_id, subcluster_id): label}
    depending on level. Uses TF-IDF over one document per cluster."""

def build_outline(
    items: list["Item"],
    assignments: list[dict],
    cluster_labels: dict,
    subcluster_labels: dict,
    existing_subcollections: dict[str, list[str]],
    input_meta: dict,
    params: dict,
) -> dict:
    """Assemble the JSON-shaped outline dict."""
```

### `litmap/cluster_render.py` — public interface

```python
def render_dendrogram_html(
    linkage: np.ndarray,
    keys: list[str],
    items: list["Item"],
    assignments: list[dict],
) -> str:
    """Plotly HTML string with hoverable leaves and level-1 colour coding."""

def render_dendrogram_static(
    linkage: np.ndarray,
    keys: list[str],
    items: list["Item"],
    assignments: list[dict],
    path: Path,
) -> None:
    """Write <path>.pdf and <path>.png at 300 DPI."""

def render_outline_markdown(outline: dict) -> str:
    """Return the Markdown outline string."""

def render_outline_json(outline: dict) -> str:
    """Return the JSON outline string (pretty-printed, 2-space indent)."""
```

### `litmap/zotero.py` — new helper

```python
def get_subcollection_map(db_path: Path = ZOTERO_DB) -> dict[str, list[str]]:
    """Return {zotero_key: [collection_names]} for every non-attachment item.
    Lists only the collections the item directly belongs to, not inherited."""
```

### `litmap/cli.py` — new command

`cluster_cmd` follows the exact structure of `map_cmd`:
- Lazy imports at the top
- `_auto_sync(db_path, zotero_db)` first
- Paper-set assembly block identical to `map_cmd`'s
- Then cluster, label, build outline, render

## Testing

New tests live in `tests/test_cluster.py` and extend `tests/test_zotero.py`. All use the existing `zotero_db` and `embeddings_db` fixtures in `tests/conftest.py`.

| Test | What it verifies |
|---|---|
| `test_compute_hierarchy_shape` | `compute_hierarchy` returns an array of shape `(N-1, 4)` |
| `test_cut_levels_three_synthetic_clusters` | Three well-separated embedding groups → three level-1 clusters |
| `test_cut_levels_respects_subcluster_threshold` | A cluster with size < threshold has `subcluster_id=None` for all its papers |
| `test_cut_levels_splits_large_cluster` | A cluster with size ≥ threshold has two or more `subcluster_id` values |
| `test_label_clusters_extracts_distinctive_terms` | Two synthetic abstract groups with disjoint vocabularies → labels reflect the separation |
| `test_label_clusters_single_paper_fallback` | A singleton cluster gets a title-based label |
| `test_build_outline_structure` | Size invariant holds; papers in sub-clustered branches live under sub-clusters, not the parent |
| `test_build_outline_existing_subcollections_attached` | Each paper's `existing_subcollections` matches the fixture Zotero DB |
| `test_render_outline_markdown_snapshot` | Markdown output matches a small pre-written expected string |
| `test_render_outline_json_roundtrip` | `json.loads(render_outline_json(outline)) == outline` |
| `test_render_dendrogram_html_smoke` | Produced HTML contains `<div id=` and a Plotly `<script>` tag |
| `test_get_subcollection_map_returns_direct_collections_only` | For the fixture DB, returns the expected `{key: [names]}` mapping |
| `test_cluster_cmd_smoke` | End-to-end: run the command over the fixture DBs and assert all five output files are created and non-empty |

## Forward compatibility — the "reorganise library" hook

The JSON output carries, for every paper, enough information for a future `litmap reorganise` command to operate without re-computing:

- `zotero_key`
- `cluster_id`
- `subcluster_id` (via nesting in `subclusters[*].papers`)
- `existing_subcollections`
- Cluster labels and sizes

No further work is required now to enable that feature.
